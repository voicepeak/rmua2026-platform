# 第二轮校准窗口的风消息审计

预先限定四个第二轮拟合进程：`d03_roll_pitch_seed2026_20261107`、`d03_roll_pitch_small_seed456_20261107`、`d04_yaw_seed2026_20261107`、`d04_yaw_small_seed456_20261107`。以每场首个发送命令的 ROS Header 时间为零点，固定检查 0.30–0.80 秒内的 `debug/wind` 消息，报告样本数、源时间覆盖、最大相邻间隔及三维风矢量最大范数；同时记录原始文件哈希、类型和解码格式。若窗口内无记录或 Header 无效，报告缺失而非当作零风。此审计不比较模型轨迹、不搜索参数、不读取独立封存集，结果不改变第二轮预先定义的筛选结果。

这是 ROS 调试消息的时间与值，不证明风在每个物理积分时刻为零，也不证明调试消息始终传递到物理引擎。先前受控注入中存在有限条件下的 ROS 与物理风矢量对应证据，但不能推广到这些自然进程。ROS Header 与物理时间、命令生效时间、碰撞和初态仍未同步或排除。

## 结果

[逐场统计、原始哈希与脚本哈希](v2_calibration_wind_audit.json)：四场各有 25 条窗口内风消息，全部观察到的矢量分量为零；窗口内相邻消息最大源时间间隔约 21.001 ms，没有非递增时间戳。四场首个样本分别位于 0.304–0.316 秒，末个样本分别位于 0.784–0.796 秒，因此窗口边界和样本间仍有未观测区间。这减少了“该窗口中调试风消息显示非零风”的疑点，不能排除实际受风或碰撞，更不能据此恢复参数搜索、解封保留集或判定 G1 通过。
