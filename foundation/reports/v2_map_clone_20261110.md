# 12 张地图不是 12 条不同赛道（2026-11-10 核对）

## 结论

`RMUA2024OL1..OL12` 是 **12 个独立地图文件**，但赛道布局是同一套几何在
世界坐标中的 **旋转 + 平移副本**，不是 12 条不同赛道。

因此：

- “OL2–OL12 是 12 张布局不同的独立地图”这一说法撤回。
- 不需要把 OL1 的检测门/道路/工厂逆向重复 12 遍。
- OL2–OL12 仍需做运行时等价性和配置差异检查；不能仅凭静态同构认定可玩/可计分。

## 文件与整体几何

- 12 套 `.umap/.uexp` 均存在，SHA-256 全不同。
- OL2–OL12 每张图 18,191 个导出 actor；OL1 为 18,215 个。
- 每图 483 条道路 actor、8,682 个建筑 placement、12 个门、12 个路线工厂 +
  1 个枢纽工厂、12 个路线端口 + 1 个枢纽端口。
- 对每张图做 yaw + 平移刚体对齐后：

| 对象 | 对齐后最大残差 |
|---|---:|
| 483 条道路 actor | 0.001–0.022 m |
| 8,682 个建筑 placement | 0.005–0.058 m |
| 12 个门 | 0.006–0.049 m |
| 12 个路线工厂/端口 | < 0.001 m（径向） |

示例：

- OL2 → OL3：yaw 约 25.5°，483 条道路最大残差 0.021 m。
- OL2 → OL4：yaw 约 173.5°，最大残差 0.020 m。
- OL2 → OL12：yaw 约 73°，最大残差 0.005 m。

每图门包围盒都约 160 m；世界位置差异来自整张图的旋转/平移。

## 路线顺序

按 `RouteIndex` 排序后，12 张图的语义顺序一致：

```text
1_1 → 2_1 → 3_1 → 4_1 → 5_1 → 6_1 → 1_2 → 6_2 → 5_2 → 4_2 → 3_2 → 2_2
```

此前文档中“OL2–OL12 是 1_1 → 1_2 → 2_1…”的说法来自 `RouteConfigs`
数组的序列化顺序，不是 `RouteIndex` 语义顺序。

## 唯一确认的配置差异

- OL1 的 `BP_GameConfig2024_2` 含完整数组：
  - 12 `RouteGateConfigs`
  - 12 `FactoryConfigs`
  - 12 `CheckPortConfigs`
  - 24 `SideTrackConfigs`
  - 24 `ArrowConfigs`
- OL2–OL12 的同一个 GameConfig 只有 12 `RouteConfigs`，上述数组均为 0。

这个差异的运行时影响尚未验证：

- 门 actor 本身在每张图都存在，OL2 的 12 个门 BeginPlay 曾与静态表匹配。
- 但 gate/factory/port 配置数组缺失是否影响计分、工厂/端口事件或可玩性，仍未知。

## 影响

1. **G2 地图工作量**：从“12 张图各自独立逆向”改为
   “OL1 全量 + OL2–OL12 刚体变换校验 + 运行时抽样”。
2. **训练环境**：不需要 12 套地图/策略；一套赛道几何 + 地图 yaw/平移随机化
   即可覆盖世界坐标变化。但不要把 OL1 世界坐标硬编码进观测/奖励。
3. **仍未知**：OL2–OL12 运行时检测组件/score 是否与 OL1 同构；
   缺失配置数组是否导致不可玩/不计分；官方 2026 如何使用这 12 张图。

## 复现

d = json.load(open('data/maps/maps_summary_all.json', encoding='utf-8'))

def loc(x):
    return (x['location']['X'], x['location']['Y'], x['location']['Z'])

def centered(points):
    cx = sum(p[0] for p in points) / len(points)
    cy = sum(p[1] for p in points) / len(points)
    cz = sum(p[2] for p in points) / len(points)
    return [(p[0]-cx, p[1]-cy, p[2]-cz) for p in points]

base = centered([loc(d['RMUA2024OL1']['gates'][k])
