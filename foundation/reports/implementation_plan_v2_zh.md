# RMUA 2026｜PWM 基础模拟器重构方案 V2.0

> **用途**：为 RMUA 2026 全赛程自主飞行研发提供**高速、可并行、可校准**的物理训练底座。  
> **日期**：2026-11-08  
> **唯一控制输入**：四电机 PWM；**不开发 VEL 训练/控制分支**。  
> **基准**：官方模拟器 `12.0.0.5`（以本机二进制、设置文件及哈希再次确认）。  
> **现状声明**：这是一份待执行的工程计划，不代表现有逆向已达到物理等价。

## 0. 先明确最终交付与边界

本次只交付一个东西：**可以用四路 PWM 驱动无人机，在官方静态赛道中以接近官方的物理行为运行，并可随机生成训练障碍的轻量模拟器**。

### 必须做的六项

| 模块 | 本轮目标 | 精度定义 |
|---|---|---|
| 1:1 静态地图 | 赛道、建筑、工厂、道路边界、门洞和相关碰撞几何 | 官方空间坐标和物理占据范围尽可能精确；未验证区域明确标注 |
| 四电机 + 6DOF | PWM → 电机状态 → 力/力矩 → 位置/姿态变化 | 以**相同 PWM 下的短时运动响应**实测校准 |
| 基础物理 | 重力、惯量、阻力、碰撞、积分、时间/延迟 | 公式可核对；运动结果经对照验证 |
| 风场 | 风区、风矢量、时变风及对机体的力/力矩 | 区分**风生成**与**风施力**，分别校准 |
| 力度衰减/静止力场 | 生效范围、实际物理作用、恢复与 2s 失败规则 | 只依据源码证据或官方实测，不写死猜测系数 |
| 车辆/细线 | 可配置、自主随机生成、移动与碰撞 | 几何及统计范围合理；**不追求 seed 逐字节一致** |

### 明确不做

- 不延续 `demo` 任一分支的原有运行架构。
- 不做视觉渲染、相机/激光雷达逐点复刻、巡检识别网络或比赛策略训练。
- 不复刻 UE4 全部场景渲染、官方随机数消费顺序和所有车辆脚本。
- 不追求完整官方裁判程序等价；**但保留门洞、碰撞、越界、超时等最小训练事件**。
- 不把“代码里的参数和官方 README 相同”称为“物理已对齐”。

**成功标准**：地图几何有来源、PWM 运动有对照数据、扰动机制有有效范围、随机障碍可复现、模拟器可批量步进。无需证明底层源码逐行一致。

## 2. 最小运行架构

```text
四路 PWM [u0,u1,u2,u3]
          │
          ▼
  指令保持 / 执行延迟
          │
          ▼
    四电机动态模型 ──→ 推力 / 反扭矩
          │                 │
          └─────────────────┘
                            ▼
                       6DOF 刚体
                      ↗    ↑    ↖
                   重力   风力   力度衰减
                            │
                            ▼
                   位置 / 速度 / 姿态
                            │
             ┌──────────────┴─────────────┐
             ▼                            ▼
       1:1 静态碰撞                  随机车辆/细线
             └──────────────┬─────────────┘
                            ▼
                    状态 + 事件 + 时间
```

不依赖 ROS、UE4 才能运行；仅**官方采集程序**需要 ROS。物理引擎先单实例正确，再向量化。外部训练器以后只需调用统一 API：

```python
sim = RmuaPhysics(map_id="OL1", seed=123, config=cfg)
state = sim.reset(initial_state=initial_state)
state, events = sim.step(pwm=[u0, u1, u2, u3], dt=physics_dt)
# state: time, position_ned, velocity_ned, quaternion, omega_body
# events: contact, gate_crossing_candidate, force_zone, timeout
# 注意：reset(initial_state=...) 是自建环境的接口，不意味着官方原生 reset 可靠。
```

### 接口固定规则

- 唯一执行动作：四路 PWM，电机次序固定；数值合法范围由消息定义及官方运行测试确认。
- 机体采用刚体 6DOF；统一 NED（m）与机体系角速度（rad/s），四元数约定写入测试。
- `physics_dt` 为模拟器积分步长；`command_dt` 为控制命令更新周期，**不得混为同一时间**。
- 同时提供：`truth_state`（仅研究/训练环境）、`observable_state`（未来可部署状态估计的接口占位）。不能让未来正式比赛策略默认读取仿真真值。
- 地图使用真实资产 ID、坐标变换、几何来源和哈希；碰撞体可使用等价简化形式，但必须记录误差。

## 3. 实施阶段：以四个关口收敛

### G0｜锁定基准与物理契约（先做）

**要做**

1. 冻结官方模拟器版本、二进制/配置哈希、AirSim 对应源码版本；保存原始运行配置。
2. 确认 PWM 消息字段、归一化范围、超界裁剪、命令保持、超时、四电机次序与旋转方向。
3. 固定 UE ↔ NED、机体系 ↔ 世界系变换及惯量参考系；实现往返单元测试。
4. 以官方发布参数建立 `quad_params.yaml`，每个参数标 `source / unit / status`。

**交付**：`baseline_manifest.yaml`、`pwm_contract.md`、`quad_params.yaml`、坐标/电机方向单测。  
**通过**：没有未知的单位和电机编号；仍未知的内部参数必须显式列入 `unknowns.yaml`，不能隐式猜测。

### G1｜只校准无风、无碰撞的 PWM 物理（核心关口）

**实现顺序**：四电机推力模型 → 电机响应 → 刚体 6DOF → 重力/阻力 → 固定步长积分 → 命令保持/延迟。

只做六种官方实验，且**不在运行中的物理采样阶段使用 GDB 断点**：

| ID | PWM 输入 | 观测与目的 |
|---|---|---|
| P01 | 四电机同幅度稳定输入 | 悬停/升降、总推力平衡 |
| P02 | 四电机共模小幅阶跃 | 推力变化、上升/下降响应与延迟 |
| P03 | 左右差分微阶跃 | Roll 符号、角速度、惯量 |
| P04 | 前后差分微阶跃 | Pitch 符号、角速度、惯量 |
| P05 | 对角差分微阶跃 | Yaw 符号、反扭矩/桨叶旋向 |
| P06 | 同波形在不同命令频率下重放 | 保持策略、有效控制时延 |

每种至少有**重复测量**与**不参与拟合的保留波形**；先用小幅度、安全时长进行辨识，再扩大动作幅度覆盖比赛预期飞行包线。初态不同的试验不可直接叠加比较，应分组或归一化后再拟合。

**交付**：`motor.py`、`quad6dof.py`、`official_pwm_recorder.py`、`compare.py`、`G1_report.md`。  
**通过**：电机方向 100% 正确，短时运动响应在冻结的测试集上满足第 5 节阈值；不能只靠悬停成功宣布 G1 完成。

### G2｜地图和碰撞（与 G1 并行）

1. 从 `re` 静态数据导入 OL1：道路、建筑、工厂、门洞及必要碰撞几何；清单中同时标记未提取/未验证区域。
2. 核查 UE 视觉 Mesh 与真实 Collision Mesh 的差异；只需**物理碰撞几何 1:1**，无需纹理、光照、场景渲染。
3. 对道路边缘、建筑外壁、门洞、工厂入口建立代表性碰撞点和净空测试。
4. 其他地图采用已有静态变换证据批量生成候选，但**不能因为门布局可刚性对齐，就默认所有障碍/建筑碰撞体一致**。
5. 加入最小门洞通过事件，单独标为训练代理事件，不冒充官方计分。

**交付**：`maps/OL1/`、`collision_manifest.json`、`G2_report.md`；之后扩至全部已确认赛道。  
**通过**：地图原点、朝向、尺度可追溯；门洞、道路关键净空和代表性墙体的碰撞结果通过；未覆盖部分有清单。

### G3｜风与力度衰减（基于已通过的 G1）

**风场分三层**：生成函数、空间/时间触发、风对机体的实际受力；优先复用 `re/local_models/wind.py` **已验证的受控生成部分**，但不把风矢量正确等同于气动力正确。

**力度衰减分三层**：区域边界、物理作用位置（PWM/电机目标/推力/外力中的哪一层）、进入/离开及超时判定。不得默认使用 `platform` 的 `thrust_scale=0.35` 或 `PWM × 常数`。

仅保留四组实验：

| ID | 测试 | 核心观测 |
|---|---|---|
| W01 | 同 PWM 条件下无风/受控风对照 | 风矢量与加速度、姿态变化的差分 |
| W02 | 穿越风区边界，保持同一动作 | 空间触发、过渡、响应滞后 |
| F01 | 力度衰减区域内外同 PWM 对照 | 动力变化层级、恢复行为 |
| F02 | 多次进出区域，接近 2s 边界 | 累计/连续计时、重置和失败事件 |

**交付**：`effects/wind.py`、`effects/force_zone.py`、`G3_report.md`。  
**通过**：风/力场的**作用方向、边界、时序和主要量级**得到独立证据；若因官方观测限制无法精确辨识，保留物理合理的参数区间并明确 `UNVERIFIED`，不能宣称已对齐。

### G4｜自主随机车辆与细线 + 批量环境（最后做）

- 车辆：可配尺寸、速度、方向、转向/停车和运动轨迹；范围优先由 `re` 资产尺寸与记录约束。
- 细线：线段/胶囊碰撞体、半径、朝向、高度、随机摆放；精度应覆盖高速穿线检测。
- 碰撞：使用扫掠检测或连续碰撞近似，测试不同 `dt` 下的漏检率；对运动障碍使用相对运动判定。
- 生成：支持 seed、固定场景、随机场景、困难场景；遵守合理的通行空间约束。
- 批量：先对比**单环境与批量环境的同 seed 轨迹**，再做 64/256 环境吞吐测试；性能不达标只优化计算实现，不重写已验收物理。

**交付**：`obstacles/`、`batch_step()`、`G4_report.md`。  
**通过**：环境可重复、障碍物碰撞不穿透；批量与单例结果一致；给出同硬件官方/自建的可复核吞吐比，而非随意承诺倍数。

## 4. 最小官方测量方式（避免过去的“测量改变结果”）

只维护三个工具：

1. `play_pwm.py`：按已知时间表发送合法四路 PWM，记录**实际发送时间**。
2. `record_official.py`：采集 `/airsim_node/drone_1/debug/rotor_pwm`、IMU、GPS、`debug/pose_gt`（如该本地研究环境确实开放）、风速及仿真时间；记录运行配置、异常/碰撞/退出。
3. `compare_runs.py`：对齐时间、坐标和初态，输出阶跃响应、状态误差、延迟及不同重复实验的方差。

规则：

- **不靠 GDB 单步获得时序数据**。反汇编/断点可以辅助定位公式，但运行时动力学采样应采用低扰动日志/官方 ROS 数据。
- 使用模拟时间戳对齐；动作发出、消息回显、动力学响应是不同事件，不假设 ROS 到达时刻就是电机生效时刻。
- 对于无法精确复位的官方模拟器，**每次实验启动新进程/容器**；记录实际初始状态，不能假装相同初态。
- 采集时将本地研究调试真值与正式比赛可用传感器明确隔离；以后训练 Actor 不允许依赖不合法真值。
- 实验样本分为**拟合集**和**保留集**；只在拟合集调整参数，保留集不能反复调参作弊。

## 5. 验收与停止规则：防止无限逆向

### 5.1 固定的衡量对象

- 短时间窗：输入后 `0–0.25s`、`0–0.5s`、`0–1.0s` 的位置、速度、姿态、角速度误差。
- 时延：输入命令、回读 PWM、首次可辨动力学响应之间的延迟与抖动。
- 动态工况：悬停、上升/下降、Roll/Pitch/Yaw、加减速、风扰动、力场衰减。
- 几何工况：门洞/墙体/车辆/细线的接触真假、最小净空和碰撞位置。
- 重复性：同官方实验重复运行的自然波动；自建环境同 seed 重放的确定性。

主要计算指标：`RMSE(position)`、`RMSE(velocity)`、`rotation_angle_error`、`RMSE(angular_rate)`、阶跃延迟误差、碰撞漏检率。报告均附单位、评测时窗与初态差异。

### 5.2 阈值如何产生，而不是事后拍脑袋

1. **先测官方重复性**：对每个波形至少 3 次独立运行，估计自然波动和时间戳不确定度。
2. **再冻结任务误差预算**：例如从门洞最小净空、预期飞行速度、控制周期、可用制动距离计算允许的短时位置/速度/姿态误差；若这些值尚未确定，先标 `PROVISIONAL`，**不能宣布“训练级精度已完成”**。
3. 在 `acceptance.yaml` 中锁定每项 `metric / threshold / test_set / time_window / source`；阈值一经冻结，只能在明确版本升级后变更。
4. 同一模块至少经过“拟合 → 保留集 → 不同初态复查”三个步骤。通过判定不依赖训练 reward。

> 若尚不能给出合理数字，则把模块标为 `PARTIAL`，但允许其他独立模块推进；不要为了凑数字编造 1%/5% 的“官方容差”。

### 5.3 强制停止条件

- **最多两轮有明确假设的模型校准尝试**：每轮写明误差来源、拟调整参数、预期改善量、结果；未改善则先停止扩展实验，提交阻塞报告和替代的可辨识实验，不是无限加 GDB 断点。
- **G1 未通过**：禁止宣称可用于高频 PWM 飞控训练；地图、几何、随机障碍仍可独立推进。
- **G3 未通过**：风与力场只可用于标注为近似的鲁棒性扰动训练，不得宣称官方一致。
- **发现不可辨识项**：保存参数区间/模型族与不确定范围；只有进入实际使用包线才值得继续逆向。
- **单实例与批量不一致**：先修数值/复位/随机数隔离，不用增加并发掩盖错误。

### 5.4 最终状态只有三类

| 状态 | 定义 | 可用于什么 |
|---|---|---|
| `PASS` | 规定场景、时窗、保留集全部满足冻结阈值 | 标注适用范围内的 PWM 物理训练 |
| `PARTIAL` | 模型可运行，但尚有未证实机制或超阈值工况 | 几何实验、原型测试、标注的随机化训练；不宣称迁移可靠 |
| `BLOCKED` | 关键测量不可获得，或误差无法归因/修正 | 暂停该模块，保存证据与下次可执行条件 |

**项目收口允许各模块有不同状态**：不是“必须全部 PASS 才能交付代码”，但绝不能把 `PARTIAL/BLOCKED` 组合成“完整 1:1 模拟器”。

| SIM-05 | 风与力场 | 两套效果模型、W/F 证据 | G3 状态明确 |
| SIM-06 | 随机车辆/细线 | 生成器与连续碰撞测试 | 可复现、无高速漏检 |
| SIM-07 | 向量化与性能 | 批量计算与基准测试 | 同 seed 单例/批量一致 |
| SIM-08 | 总体验收 | 各模块 PASS/PARTIAL/BLOCKED 汇总 | 有证据、限制、可用包线 |

**推荐执行序列**：`SIM-01 → SIM-02 → SIM-03` 为主线；`SIM-04` 并行；随后 `SIM-05`；最后 `SIM-06 → SIM-07 → SIM-08`。没有必要等待全地图完成才能测电机，也不必等风场完成才能测试碰撞。

## 7. Definition of Done（本轮最终交付）

- [ ] 可在无 UE、无 ROS 的环境中，使用四路 PWM 稳定推进单机 6DOF 状态。
- [ ] 基础 PWM 模型已在官方对照中给出量化误差、适用包线与通过状态。
- [ ] 已有可查询、可碰撞、可追溯的官方静态地图；未覆盖区域显式列出。
- [ ] 风、力度衰减模型各自有独立的验证/不确定性报告。
- [ ] 车辆与细线可随机生成，碰撞检测在高速场景不明显漏检。
- [ ] 同 seed 单机/批量结果一致，附原始吞吐基准。
- [ ] 提供一个 `run_smoke_test.py`，能演示：初始化 → PWM 起飞/运动 → 风/衰减 → 障碍接触 → 结束。
- [ ] `foundation_acceptance.md` 明确哪些模块已通过、哪些仍待验证、哪些工况**禁止声称官方等价**。

**一句话收口**：本轮不训练比赛策略，也不承诺一比一还原官方全部内部实现；只交付一个**以 PWM 为唯一动作、关键动力学有实测依据、地图与障碍能用于后续全赛程训练**的基础模拟器。
