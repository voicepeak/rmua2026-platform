# PWM 契约（G0：PARTIAL）

官方相关历史 ROS 消息快照为 [RotorPWM.msg](../evidence/RotorPWM.msg)，有 Header 和 `rotorPWM0` 至 `rotorPWM3` 四个 `float64`；当前采集器以相同字段生成消息并核对 MD5。消息格式本身不能证明官方可接受数值范围、越界处理或物理应用时刻。

公开资料给出的编号顺序为 0 右前、1 左后、2 左前、3 右后；已有个别电机历史脉冲摘要，但完整原始数据不在证据目录，尚不足以单独验证每个电机旋向。运行时按地址排序与通道的对应也仅在特定短波形及进程中受支持，不应推广为普遍契约。证据和限制见 [来源说明](../evidence/README.md)、[电机映射实验](kinematic_mapping_protocol.md)。

自建 `Quad` 当前要求 PWM 为有限的四元向量且每项在 0–1 范围，否则拒绝；这是自建模型输入规则，**不是官方裁剪或范围已验证**。指令保持、超时、实际生效延迟、源时钟与物理时间关系均未确认，见 [未知项](../config/unknowns.yaml)。

对历史 `source_snapshot.tar.gz` 的目录清点仅找到消息定义、实验发布代码及其测试，未找到可确认发布版服务端 PWM 裁剪或超时行为的实现。逆向仓库保存的 `moveByMotorPWMs` 反编译片段涉及等待和命令回调，但仅凭该片段不能确定 ROS 入口、物理应用或超时后的行为；不能把客户端自己的输入检查当成官方契约。

世界坐标与机体旋转约定见 [坐标基线](../frame_spec.md)；UE cm ↔ 假定轴对齐 NED m 的位置往返测试不证明真实地图原点和旋转已正确。参数及其来源状态见 [参数表](../config/quad_params.yaml)。G0 的方向、单位和完整运行配置尚未完成确认，不能标记 PASS。
