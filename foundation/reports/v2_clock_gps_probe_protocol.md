# G0/G1 ROS 时钟与 GPS 采集核查

采集前固定：使用正常 50 Hz `collective` 波形和既有保护，以 seed 77771 启动新的非 GDB 官方进程；采集器在已有位姿、IMU、PWM 回显、风消息之外记录 GPS PoseStamped、`/clock`（如有）和启动时 `/use_sim_time`、ROS 当前时间及话题列表。不改变控制波形或参数。

报告各话题消息数、非零时间戳数、单调性及起止时间，比较窗口内源时间与主机到达时间间隔；未收到的话题明确标记未观测。`/use_sim_time=false` 或无 `/clock` 不自动证明官方物理按真实时间推进，ROS Header 的来源和动作生效时刻仍需独立确认。此采集为工具与时钟诊断，不是保留集或 G1 验收。

结果见 [原始统计与哈希](v2_clock_gps_seed77771.json)：启动时 `/use_sim_time=false`，话题列表未显示 `/clock`，采集期间也未收到 `/clock`；GPS 话题存在并收到 33 条，另收到 338 条位姿、337 条 IMU、338 条 PWM 调试消息。0.30–0.80 秒主机窗口内，各有数据话题的源时间/到达时间推进比约 0.997–0.998；源 Header 与主机墙钟到达的中位差约 21 ms。该差包含时钟偏移、消息生成、排队与处理，不能解释成传感器或电机的物理延迟；单次无断点结果也不能证明其他负载下实时性。

PWM 回显 Header 的同版本静态来源为单独请求的 IMU 数据时间，而非 PWM 样本自身时间；因此该话题的 Header 与 IMU 同步不构成独立交叉验证。详见 [传输证据](v2_ros_transport_evidence.md)。
