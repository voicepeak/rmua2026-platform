# 自由落体时钟一致性审计（探索性）

本页分析现有无断点采集里、指令归零后的自由落体尾段。**窗口准则是查看数据后确定的**，因此这是探索性证据，不是预先冻结的验收测试，也不改变 G1 的 BLOCKED/PARTIAL 状态。

## 方法

- 只使用已保存的 `foundation/datasets/*/capture.jsonl` 和 `commands.jsonl`；不启动官方模拟器、不使用 GDB、不读取封存保留集。
- 在最后一条非零 PWM 指令后至少 0.05 s 开始，寻找连续姿态段：时长 0.15–0.35 s、竖直下落 0.1–0.6 m、无跳变、IMU 机体 z 轴比力均值绝对值 < 0.05 m/s² 且最大值 < 0.5 m/s²。
- 对同一段分别用 ROS Header 源时间和主机到达时间拟合 `z = a + v t + 0.5 A t²`；比较拟合加速度 `A` 与 `g=9.80665`。
- 机器可读结果与源文件哈希见 [v2_ballistic_clock_audit.json](v2_ballistic_clock_audit.json)，命令：

```powershell
.\.venv\Scripts\python.exe -m foundation.audit_ballistic_clock
```

## 解释

1. 在这两个短窗口内，ROS Header 源时间给出的竖直加速度与重力相差约 0.17–0.24%，二次拟合残差约 0.01–0.02 mm；主机到达时间给出的加速度偏差约 1.0–1.1%，残差约 1.1 mm。差异主要来自到达时间抖动/乱序，而不是源时间尺度。
2. 这支持“姿态源时间在该窗口内是均匀物理时间”的候选解释，也解释了此前源时间映射回放优于到达时间回放的现象。它是 `clock_mapping` 的部分证据，不是完整时钟校准。
3. 拟合加速度略低于 `g`，可能来自残余推力/阻力、姿态段并非完全自由落体、`g` 取值或姿态滤波；不能把 9.783/9.790 当作新的重力或时间尺度实测值。
4. 四组使用同一波形和相近初态，不是独立波形重复；其中两组进程被 motion guard 中止；窗口准则是事后选择的；没有覆盖指令生效时刻、电机状态、独立初速度、接触或风。
5. 因此 G0/G1 仍不能宣布通过；G1 的参数辨识仍为 **BLOCKED**。该证据只能把“源时间完全不可用作物理时间”的悲观假设收窄为“在这两个自由落体窗口内可用”，并支持后续用源时间做低扰动时钟核查。
