# PWM 发布与调试回显审计

使用 [pwm_echo_audit.py](../pwm_echo_audit.py) 解码并检查消息类型、MD5、Header、数据长度和数值，按实际发送 PWM 变化划分时间窗；每个窗记录前一条调试值、首个数值匹配消息的主机到达时间和 ROS Header 时间。若前值已匹配或无前值，明确标记对应关系有歧义。

在两次横滚/俯仰和一次偏航运行的 19 个输入阶段中，各阶段在下一阶段前均出现数值匹配的调试消息；首个匹配的主机到达时间比命令发送后记录时间晚约 16.7–63.9 ms。两次匹配消息的 Header 时间早于命令 Header，分别约 -2.3 和 -5.1 ms。明细与哈希：[横滚/俯仰 314159](v2_echo_roll_pitch_seed314159.json)、[横滚/俯仰 27182](v2_echo_roll_pitch_seed27182.json)、[偏航 27182](v2_echo_yaw_seed27182.json)。

命令记录发生在发布之后，消息到达包含 ROS 与进程调度；消息 Header 的时钟语义和回显与实际电机的关联尚未确认。重复数值、采样时序和延迟都可能影响匹配；这些时间差不是已辨识的控制延迟、电机延迟或首次物理响应。负 Header 时间差说明不能仅按匹配值断定一一因果关系。

补充：同版本 ROS 库的静态证据表明，PWM 回显的数值和 Header 来自两次不同请求，Header 取自 `GET_IMU_DATA`，因此不能将该 Header 减去命令 Header 解释为 PWM 采样延迟。相关六场历史无断点 ROS 层探针及哈希见 [传输证据](v2_ros_transport_evidence.md)；物理时刻仍未知。
