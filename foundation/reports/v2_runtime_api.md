# V2 单环境 PWM 接口

`foundation.runtime.RmuaPhysics` 包装现有候选 `PhysicsSim`，每次 `step(pwm, dt)` 接受四个数值，持续保持到此次命令结束、碰撞或超时。`dt` 是命令保持时间，必须为构造时 `physics_dt` 的整数倍；每个固定步长调用一次底层物理。默认候选输入范围 [0, 1] 不是官方裁剪已验证的证据。

```python
from foundation.quad import Params
from foundation.runtime import RmuaPhysics

# 以下数值仅用于演示接口，非官方验收参数。
p = Params(.9, (.0046890742, .0069312, .010421166), .18, 12., .16, .01)
sim = RmuaPhysics(p, physics_dt=.0025, timeout_s=5.)
observation = sim.reset(initial_state={'rotor_signal': [.18] * 4})
observation, events = sim.step([.18] * 4, dt=.02)
research_truth = sim.truth_state()  # 显式访问仿真真值
```

默认返回的 `observable_state` 为 `None`，是未来状态估计器的占位，**不是**已经实现的传感器模型或比赛可用状态。`truth_state()` 是显式研究接口；策略使用者不得将其误当作合法比赛观测。事件包括候选碰撞、门通过、力场状态和候选计时，以及自建环境超时；候选状态并非官方裁判结论。

可选 `flight_bounds_ned_m=[[xmin,ymin,zmin],[xmax,ymax,zmax]]` 显式设置 NED 米制候选轴对齐边界；默认不启用，`ScenarioFactory` 的障碍生成边界不会自动成为飞行边界。每个物理步末检查无人机中心，首次在边界外时返回 `out_of_bounds_candidate=True` 并终止；初始位置在界外的重置会报错。边界面本身算界内，不考虑机体半径，未求精确越界时刻，也无法检测单步内离开后又返回的轨迹。门穿越与越界落在同一物理步时，穿越进入 `ambiguous_gate_crossing`。这只是调用方指定的训练代理，并非已验证的官方越界规则或赛道范围；批量接口使用顺序参考路径。

碰撞检测目前不提供精确接触时刻。如果碰撞和候选门平面穿越发生在同一物理步，无法判断先后，接口将其放入 `ambiguous_gate_crossing`，不会放入 `gate_crossing_candidate`；之前物理步已发生的候选穿越仍保留。两类均只是几何代理事件，不能当作官方计分；碰撞终点仍是发生碰撞的子步末位置。

每次返回的事件同时包含 `physics_status`、`map_status`、`wind_status` 和 `force_degradation_status`，以提示模型缺失或候选状态；这些标签不是机器可自动推导的官方验收结果。

地图显式启用封闭网格实体假设时，`map_containment_unknown` 汇集命令期间遇到的开放网格或包含关系不确定项；它非空时不能把无碰撞事件当作已经确认的净空。

地图、风、力场和障碍通过底层 `PhysicsSim` 的可选构造参数显式配置；此接口本身不保证完整地图、官方物理或不同进程时钟同步。候选种子场景可通过 [ScenarioFactory](v2_scenario_factory.md) 构造。力回放和记录效果的时间覆盖会在执行前检查；即使路径可能提前碰撞，未覆盖的整段命令仍会被保守拒绝。G1/G2/G3/G4 不因接口存在而通过。

启用候选空间力场，或启用包含衰减状态的记录效果时，必须显式指定 `field_rotor_target_scale`（0–1）；否则构造报错。事件返回该数值和候选状态。旧调用方若依赖隐式 0.25，需按自己的证据明确传入 `field_rotor_target_scale=.25`；这不表示自然场景已经验证为固定 0.25。仅记录风且所有力场标志均为正常的回放不需要衰减系数。

候选生成风可通过 `CandidateWindField` 接入：调用方需明确提供风生成器、源坐标到 NED 的正交变换、NED 空间范围和时钟偏移，并另外配置 `DragFaces` 等气动力模型。每个物理步先采样该区域的风，再由气动力模型施力；数据时间覆盖不足会在命令执行前拒绝。不能同时使用另一条记录风或手动风输入。该区域、时钟和坐标转换是调用方的候选假设，不是已验证的官方风区或施力规则。

风关键帧生成使用每次独立创建的纯 Python 随机数流；本地测试覆盖不同 seed 交错生成以及时间倒序采样。同一 seed 的结果不保证与官方自然赛程一致，因为官方可能在风生成前消费随机数。采样器按官方候选实现使用 float32 时间，若输入四舍五入后落在最后关键帧之外，将拒绝采样，避免复用旧索引；相邻关键帧若在 float32 中重合也会被拒绝。

## 参考批量接口

`foundation.batch.BatchRmuaPhysics` 接收互相独立的单环境实例；`batch_step(pwm, dt, active=...)` 接受 N×4 PWM 和逐环境布尔掩码，终止环境必须通过掩码跳过或单独重置。动作形状、活动环境的输入和已知回放窗口在推进任何环境之前检查；如果用户提供的任意自定义组件在执行中抛错，无法保证整批回滚。调用方必须为各环境隔离自身有状态的回调、随机生成器及自定义模型；内建可变力场计数器不能共享。

默认 `backend='auto'` 对至少两个活动环境的**无地图、无障碍、无风、无力场、无门、无回放和无超时**自由飞行使用 NumPy/SciPy 向量化计算；任何不满足条件的批次使用原逐环境顺序参考实现。`backend='reference'` 强制使用参考实现，`last_backend` 标示上次调用所走路径。测试覆盖不同物理参数、初态、随机动作、活动掩码的逐步状态与事件对照，并检查碰撞及记录型力场自动回退；这是自建模型之间的一致性，不是官方对齐。

64/256 环境的三次本机自由飞行测试、输入哈希、每次耗时、单环境对照及误差见 [向量化基准报告](v2_batch_vectorized_benchmark.json)；历史顺序实现的一次测量保留在 [参考基准](v2_batch_reference_benchmark.json)。运行 `python -m foundation.benchmark_batch_vectorized` 可重测。上述结果没有同机官方模拟器对照，不可表述为官方加速倍数；G4 的完整场景一致性、全场景向量化及真实性能验收仍未完成。

进一步以合成场景检查了候选墙面、门事件、风、力场、线障、移动车辆和超时：四个环境的每步状态和事件与各自独立单环境一致，并覆盖线障、车辆、墙面与超时四种终止。另有 [64/256 环境配置场景基准](v2_batch_scenario_benchmark.json)：加载 508 个 OL1 候选实例，同时配置候选风、力场、线障和移动车辆，批量回退与单例的末态及最终事件相同。但起点有意放在远离地图和障碍的位置，所以这不衡量实际密集碰撞查询或赛道运行吞吐；无同机官方基准，数值不能外推为官方相对速度。

新增 [候选地图表面接触基准](v2_batch_map_contact_benchmark.json)：64/256 环境各执行一个 0.01 秒指令，初态以约 100 m/s 朝同一 OL1 道路候选面运动。默认 508 实例场景两次短测中位约 645/637 环境命令每秒；四个既有可选组 12,117 实例场景约 570/576（该基准早于后续 12 建筑 + 480 货架 cooked 网格回退，不是当前六组全可选计数）。全部环境都报告候选地图碰撞，逐环境事件与独立单例相同、状态最大差为 0。该初态是构造的高速接触，同一局部空间筛选仅命中两个候选实例，不能代表密集场景或完整航线；未包含扰动及官方同机基准，也不验证官方碰撞几何或响应。

新增 [密集候选地图负载基准](v2_batch_dense_map_benchmark.json)：加载 OL1 六个可选组共 12,609 个候选实例，64/256 个环境分别从不同候选表面采样初态，各执行一个 0.01 秒高速接近指令。两次短测中位批处理吞吐约 777.2/710.9 环境命令每秒，独立单例约 777.0/716.5；全部 64/256 个环境都报告候选地图接触，批量与单例事件及末态一致，状态最大差为 0。该基准仍使用顺序参考路径，不是向量化加速结论；单次局部查询的中位候选筛选数约 2，不能代表官方密集赛道分布，也没有同机官方吞吐对照。候选变换、碰撞通道和接触响应仍未验证，G4 保持 PARTIAL。
